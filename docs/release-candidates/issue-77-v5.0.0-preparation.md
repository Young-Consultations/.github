## Offline canary contract and future live transport

The offline module in #103 is deliberately pure: synthetic plan binds target, executor SHA, control-plane SHA, base SHA, environment, receiver and policy revision; deterministic marker and stable branch identity. Fake fresh path attempts one push and one draft; verified replay performs zero mutations; resume existing owned branch may create one draft. Unreadable state, foreign ownership, multiple PRs, non-draft/closed PR, head/base mismatch, permission/dry-run failure and binding drift deny. Ambiguous creation performs one reconciliation read and no second create in the simulation. The simulator cannot emit readiness-eligible evidence, read secrets or reach a network.

Live transport remains **unimplemented**. Require exact reviewed tag and protected owner approval; no user task/portfolio approval input, OpenAI key, router or result-writer credential. Same actual publisher credential as production; use fixed allowlisted repository/paths and stable identity; verify base/head/marker, author and draft-only status from GitHub. Check push/PR automation will not cause paid reviews or deployment. No forced writes, merge, ready-for-review, deletion, cleanup, or repeated create on uncertain response. Persist/reconcile uncertain outcome across runs; after any ambiguity do not allow another creation merely because a read is empty. A real transport must handle concurrency/ownership races and eventual consistency, with bounded timeouts and one mutation attempt per stage. Only operator may clean up. Capture safe GitHub links and immutable identities; protected owner attestation with exact token fingerprint, timestamp and policy revision is separate from simulator. Never log or commit credential values/fingerprint. Existing gate max age 30 days; owner invalidates on policy change or permission concern, no guarantee against later revocation. No live canary or provisioning authorized in this preparation.
