# Requirements Traceability Matrix

## Traceability policy

This matrix covers every normative requirement in the baseline. The source codes and business goals are defined in the [baseline index](README.md) and [PRD](project-requirements.md). “Responsibility” allocates the requirement to a repository capability, not an implementation component. Acceptance criteria remain normative in the linked source requirement; the matrix points to them without duplicating and risking drift. Future test IDs are reserved for the verification plan. Architecture decisions, epics, stories, design elements, test cases, and evidence shall add the requirement ID and maintain reverse links. No orphan downstream item may enter Ready.

## Downstream trace schema

Each architecture/design/backlog/test artifact shall record: baseline version, requirement IDs, interface IDs, decision/evidence link, owner, and status. Verification results shall record test ID, requirement revision, environment, input identity, expected/actual result, evidence URI, executor, timestamp, and disposition. A requirements change shall trigger impact analysis over all linked artifacts before approval.
