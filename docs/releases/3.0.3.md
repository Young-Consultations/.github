# AI-SDLC 3.0.3 cross-release admission reuse repair

**Status:** published PATCH compatibility release; deployed preflight, source cutover, and REAL acceptance pending.

The lightweight `ai-sdlc-v3.0.3` tag resolves exactly to reviewed PR #104
merge commit `f3229bfa4a06da963cae7c390c6075b4f6c12f7b`. Published `ai-sdlc-v3.0.2` remains immutable
predecessor evidence, and portfolio-tasks currently consumes 3.0.2. This release
repairs organization issue #103 / consulting-playbook DEF-0086 without moving
or reinterpreting any previously published tag.

## Defect

After #159's latest failed target attempt was reconciled, the source preserved
the original trusted 3.0.1 admission for logical delivery
`task-b72eaf2503fc3d27c82f8921e8cfbfff` and cleared `status:queued`.

Published 3.0.2 would still reject the next unchanged authorized retry because
the router regenerated admission release/activation evidence from the current
release and compared it for exact equality with the durable 3.0.1 admission.

That made the documented cross-release recovery path impossible even though the
3.0.2 receiver compatibility policy explicitly accepted the predecessor
admission.

## Resolved design

Admission evidence belongs to the logical delivery.

For an existing trusted router-owned admission, the router now:

1. preserves immutable contract, delivery, correlation, source, and target
   identity;
2. accepts exact same-release full-binding reuse without consulting the
   predecessor allowlist;
3. permits cross-release reuse only when the existing admission release appears
   in the target's immutable `reusable_admission_releases` policy;
4. requires target compatibility verification to prove that reuse set is a
   subset of the exact pinned receiver compatibility allowlist;
5. re-queries the admission journal after creating its identity marker and
   rejects concurrent, ambiguous, malformed, unsupported, or conflicting
   state before target dispatch; and
6. creates a new current-release admission only for a new logical delivery.
