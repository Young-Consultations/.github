## Why this PATCH exists

Controlled REAL issue
[Young-Consultations/portfolio-tasks#159](https://github.com/Young-Consultations/portfolio-tasks/issues/159)
was admitted by `ai-sdlc-v3.0.1` and dispatched to the reviewed
`codex-adapter-v3.0.0` target. Target run
[36480321187](https://github.com/Young-Consultations/consulting-playbook/actions/runs/36480321187)
proved the dedicated result-writer GitHub App credential path healthy and then
produced a canonical failed result after Codex returned no candidate changes.

The target's immutable `ai-sdlc-v3.0.0` receiver rejected that otherwise valid
result because the receiver required the admission marker's
`control_plane_release` string to equal the receiver bundle release string.
That implementation contradicted the reviewed 3.0.1 composition, which
explicitly allowed the 3.0.1 source/control plane to reuse the 3.0.0 target
receiver.

The reusable workflow inputs, payload schema, result-writer identity, and
source projection event remain unchanged. The repair replaces accidental
version-string equality with an immutable reviewed compatibility policy, so it
is a PATCH implementation correction.

## Receiver compatibility policy

The receiver bundle now contains
`config/codex-result-receiver-compatibility.json`.

The policy:

- names the exact receiver/control-plane release owning the bundle;
- contains an explicit allowlist of accepted admission releases;
- is loaded only from the immutable receiver bundle, never from caller input;
- requires the receiver's runtime release identity to match the policy;
- rejects an admission whose recorded control-plane release is absent from the
  allowlist; and
- is validated by release and target-compatibility tooling.

For published 3.0.2, the reviewed admission set is:

- `ai-sdlc-v3.0.1`, solely to permit recovery/redelivery of already admitted
  delivery `task-b72eaf2503fc3d27c82f8921e8cfbfff` from issue #159 without
  fabricating a new delivery identity; and
- `ai-sdlc-v3.0.2`, for new admissions after consumer adoption.

No earlier release is implicitly accepted.

Regression coverage reproduces the original split-release condition by
exercising a reviewed 3.0.0 receiver compatibility policy that accepts a 3.0.1
admission. Unreviewed admission releases and runtime/policy mismatches fail
closed.
