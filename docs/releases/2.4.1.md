# AI-SDLC 2.4.1 stabilization release

**Status:** published; `ai-sdlc-v2.4.1` resolves to
`34ec7dc1cf54f960757781851384e0f6b15f7b63`.

This patch stabilizes the existing v2 path without changing the closed payload
schemas or removing the retained source result projector. Published 2.4.0 remains
immutable and is the rollback baseline.

## Release composition

- Source consumer: `portfolio-tasks` pins `codex-router.yml@ai-sdlc-v2.4.1`.
- Router: the reusable workflow self-pins `actions/codex-router@ai-sdlc-v2.4.1`.
- Activation: one checkout of `config/codex-activation.json` from `main`; the
  router records the checkout revision and content digest in admission evidence.
- Enabled target: only `consulting-playbook`, pinned to immutable
  `codex-adapter-v2.4.1`.
- Receiver: the enabled target pins `codex-result-receiver.yml@ai-sdlc-v2.4.1`,
  whose workflow self-pins its receiver action to the same release.
- Current operating truth: `release/current-runtime.json`, generated from the
  release manifest, capability registry, activation, and credential-role manifest.

## Completed publication sequence

1. Merge the reviewed control-plane candidate without publishing its tag.
2. Merge the consulting target change after complete zero-effect conformance,
   then create `codex-adapter-v2.4.1` at that reviewed commit.
3. Bind the target tag, commit, and report digest in a final control-plane PR,
   keeping `tag_published` false and `tag_commit_sha` null.
4. Merge that PR, confirm `ai-sdlc-v2.4.1` is unused, and create the immutable
   control-plane tag at the reviewed merge commit.
5. Record the resolved tag commit SHA in this publication attestation, set
   `tag_published` true, regenerate the runtime record, and pass the publishable
   release gate. Runtime Preflight independently resolves the remote tag and
   requires it to match the recorded commit. REAL preflight runs the current
   attestation verifier against SIM evidence generated from the immutable tag;
   it does not require the later attestation commit to equal the earlier tag.
6. Merge the portfolio consumer only after the control-plane tag resolves,
   during a controlled approval freeze.
7. Run Runtime Preflight, SIM, one live verify delivery, and one harmless REAL
   implement delivery. Confirm redelivery reuses the same managed draft.

## Required checks

```console
python3 scripts/generate_current_runtime.py --check
python3 scripts/runtime_preflight.py --offline
python3 scripts/validate_release.py --require-publishable
python3 -m pytest
```

The manual Runtime Preflight workflow checks the deployed configuration and the
presence of credential/variable names without reading or printing secret values.
Its deployed mode resolves the remote tag and compares it with the explicitly
attested commit before checking credential metadata.
Actual least-privilege behavior is proven by SIM, live verify, and the bounded
REAL acceptance run.

Do not enable another target or begin v3 migration until three consecutive
deliveries complete cleanly on this composition.
